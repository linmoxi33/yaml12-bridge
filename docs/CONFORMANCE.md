# Conformance notes

Everything below was measured on this machine, with these versions:

| implementation | version | role |
|---|---|---|
| PyYAML | 6.0.3 | the 1.1 reference (it is what the affected projects use) |
| ruamel.yaml | 0.19.1 | 1.2 reference, round-trip oriented |
| js-yaml | 4.1 | 1.2 reader, very widely deployed |
| `yaml` (npm, eemeli) | 2.x | 1.2 reader, strict spec reading |
| yaml12-bridge | 0.1.0 | this package |

Reproduce with `python bench/timing.py` for speed and the snippet at the bottom
for the scalar matrix.

## Why PyYAML is the 1.1 oracle

"YAML 1.1" is not one fixed semantics. Two implementations both claiming 1.1
disagree:

```
PyYAML 6.0.3     yaml.safe_load("k: 1e3")   -> '1e3'    (string)
yaml npm 1.1     YAML.parse("k: 1e3", v1.1) -> 1000     (number)
```

PyYAML requires a dot in the mantissa for a float, per the 1.1 float type; the
`yaml` package reads JSON-style numbers in 1.1 mode too. Neither is "wrong" --
the 1.1 spec is ambiguous enough to allow both.

Since this package exists because of PyYAML's behaviour, PyYAML is the correct
oracle for "what did this file mean before". Using anything else would test
against a semantics nobody was actually running.

## The three rows where implementations disagree with each other

### `1_000` — spec says string, ruamel says int

The 1.2 Core Schema integer rule is:

```
[-+]? [0-9]+ | 0o [0-7]+ | 0x [0-9a-fA-F]+
```

No underscore separator. `1_000` is therefore a **string** in 1.2, and both
js-yaml and the `yaml` package agree. ruamel accepts underscores for
backwards compatibility with 1.1 files.

This package follows the spec. The practical consequence is that
`--mode value` will quote a `1_000` that came from a 1.1 file, because 1.1 read
it as 1000. That is the safe direction: quoting cannot lose data, whereas
leaving it bare means ruamel and js-yaml disagree about the type.

### `2001-12-14` — the spec has no timestamp type

The 1.2 Core Schema defines exactly five types: null, bool, int, float, str.
There is no timestamp. A spec-literal reader returns the string.

ruamel and PyYAML construct `datetime.date` anyway, because dropping timestamp
support would break a lot of real files. js-yaml and the `yaml` package return
strings.

This package defaults to the spec and exposes the other reading:

```python
yaml12bridge.load("d: 2001-12-14")["d"]                          # '2001-12-14'
yaml12bridge.load("d: 2001-12-14", options=LoaderOptions(timestamps=True))["d"]  # date(2001, 12, 14)
```

Because two of three implementations construct dates, `needs_quotes()` treats a
date-shaped string as needing quotes when *dumping*. Quoting a date string is
always safe; failing to quote one is not.

### `0b101` — 1.1 binary, not in 1.2 Core

1.1 supports `0b` binary; the 1.2 Core Schema does not. ruamel keeps it for
compatibility. This package and the two JS readers return the string.

Consequence: a 1.1 file with `flags: 0b101` (value 5) needs migration, and
`--mode value` rewrites it to `5`.

## What was verified, and how

### 1. Scalar semantics, against three implementations

`tests/test_schema.py` pins each scalar to the tag and Python value it must
produce. The matrix above was generated by running every implementation on the
same inputs, not transcribed from documentation.

Two bugs were found this way during development, both kept as regression tests:

* **Resolution order.** `0644` matches both the 1.2 int and float patterns.
  The spec resolves null → bool → int → float; putting float first turned file
  modes into floats. Fixed in `schema.py` with a comment explaining why the
  order is load-bearing.
* **Prefix matching.** PyYAML's `BaseResolver.resolve` calls `regexp.match`,
  which is a *prefix* match. Handing it unanchored spec regexps made `12:30`
  resolve as int 12. Every pattern is now wrapped in `\A(?:...)\Z` at table
  build time.

### 2. Migration correctness, across implementations

`bench/crosscheck.js` is the check that actually proves the claim, because it
does not share code with the migrator:

1. `bench/legacy_reference.py` reads each sample with **PyYAML** (1.1) and dumps
   the flattened result to JSON.
2. `crosscheck.js` reads each *migrated* sample with the **`yaml` npm package**
   (1.2) and compares.

Result on the four sample configs: **108 scalars compared, zero mismatches** in
`--mode value`, in both directions of the boundary.

Key names are normalised (`True` ↔ `on`) before comparison: PyYAML maps a bare
`on:` key to boolean `True`, and after migration the quoted `'on':` reads as
`"on"` in **both** schemas. That is the fix working, and comparing raw key text
would report it as a failure.

### 3. Round-trip through the dumper

`tests/test_migrate.py::TestDumperQuoting` asserts that a value survives
`load → dump → load` through *our* loader, through PyYAML, and through ruamel.
The third one is the important one: PyYAML reads its own ambiguous output back
happily, which is exactly why the bug went unnoticed upstream for years.

### 4. Real-world corpus

`tests/corpus/` holds 12 Playwright accessibility snapshots from a real browser
session (40 KB, deep nesting, Unicode, bracket-heavy keys). They are not
synthetic. One contains music durations like `4:56`, which PyYAML reads as the
sexagesimal integer 296 -- the tool correctly reports and rewrites it.

### 5. Performance, measured honestly

`bench/timing.py` compares against both PyYAML loaders. The naive comparison
(`yaml.safe_load`) makes this package look 5x faster, which is false: `safe_load`
wraps the *pure-Python* loader while this package defaults to libyaml. Against
PyYAML-on-libyaml the overhead is 1-15% on real files and within noise at
636 KB.

## Reproducing the matrix

```python
import warnings; warnings.simplefilter("ignore")
import yaml
from ruamel.yaml import YAML as Ruamel
from yaml12bridge import load

cases = ["NO", "on", "12:30", "0644", "1_000", "1e3", "3900e128", "2001-12-14"]
for c in cases:
    print(
        f"{c:12} "
        f"pyyaml={yaml.safe_load('k: ' + c)['k']!r:20} "
        f"yaml12={load('k: ' + c)['k']!r:20} "
        f"ruamel={Ruamel(typ='safe').load('k: ' + c)['k']!r}"
    )
```

```console
cd bench && npm install yaml && node crosscheck.js
```
